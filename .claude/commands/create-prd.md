# Create Product Requirements Document

Based on our discussion, create a comprehensive PRD at `_docs/PRD.md`.

Follow this structure:
1. Executive Summary — what this product does and why it exists
2. Problem Statement — the gap being filled
3. Target Users — who, with specificity
4. Success Metrics — measurable outcomes, not vibes
5. Core Features — user stories with acceptance criteria
6. Non-Functional Requirements — performance, accessibility, reliability
7. Technical Constraints — platform, dependencies, known limits
8. Timeline — phases with clear deliverables

Before writing: ask clarifying questions to close any gaps. Use ultrathink for planning.

After writing: surface the top 3 open questions that still need answers before implementation begins.
